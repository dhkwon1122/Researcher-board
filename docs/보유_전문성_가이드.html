보유 전문성 기능 안내

대시보드의 "보유 전문성" 화면이 무엇을 보여주고, 그 내용이 어떤 데이터와 절차로 만들어지는지 설명합니다.

① 화면 구성 ② 만들어지는 과정 ③ 결과를 읽을 때 유의할 점 ④ 참조 파일 부록: 실행 순서

①화면 구성 — 4개 탭

"보유 전문성"은 연구원 개개인의 실제 전문성(과제명이 아니라 실제로 어떤 기술/지식을 갖고 있는가)을 사내 LLM과 임베딩으로 분석해 보여주는 화면입니다. 좌측 사이드바의 조직도를 통해 부서/과제 단위로 찾아 들어갈 수 있고, 이름·사번으로 바로 검색할 수도 있습니다.

연구원

연구원별 보유 전문성 카드

학력·과제 이력·직무 이력·핵심기술·보유기술·논문·특허를 종합해, 연구원 한 명 한 명의 강점 분야/키워드/Hard Skills/Domain Knowledge를 카드로 정리해 보여줍니다.

연구원 ↔ 연구원

전문성이 비슷한 사람 찾기

과제가 완전히 달라도(예: A과제 vs B과제) 실제 보유 전문성이 겹치는 연구원을 찾아 보여줍니다. 시니어를 먼저, 그다음 주니어 순으로 표시하며, 근거 없이 점수만 높은 매칭은 제외합니다.

연구원 ↔ 과제

과제·직무와 연구원 매칭

"과제 기준"(이 직무에 맞는 사람은 누구인지), "인별 기준"(이 사람에게 맞는 과제·직무는 무엇인지), "과제 전문성"(과제별 필요 전문성 딥다이브)을 한 화면에서 오가며 볼 수 있습니다.

전문성 MAP

전사 전문성 지도(산점도)

모든 연구원의 전문성을 2차원 지도 위에 점으로 뿌려, 가까이 모인 점일수록 실제로 비슷한 일을 하는 사람들임을 한눈에 보여줍니다. 이름/사번으로 검색해 위치를 바로 확인할 수 있습니다.

②어떻게 만들어지나

네 개 탭은 모두 같은 5단계 파이프라인 위에서 만들어집니다. 사람이 매번 새로 작성하는 것이 아니라, 아래 단계를 스크립트가 순서대로 실행해 데이터를 준비합니다.

1 원본 정리 인사·과제·조직도 엑셀을 표준 형식(csv/json)으로 정리
→
2 전문성 추출 (LLM) 연구원·과제 각각의 이력을 사내 LLM에 분석시켜 핵심 분야/키워드/필요 기술 도출
→
3 임베딩 추출된 전문성 설명을 BGE-M3로 숫자 벡터화 — 의미가 비슷하면 벡터도 가까워짐
→
4 매칭·유사도 (LLM) 벡터로 후보를 추린 뒤, LLM이 실제로 근거 있는 유사/적합인지 한 번 더 정성 판정
→
5 화면 표시 결과를 콘솔형 리포트/지도로 렌더링해 대시보드에 그대로 띄움

왜 임베딩과 LLM 두 단계를 다 쓰나요?

임베딩(3단계)만으로는 "왜 비슷한지"를 알 수 없고, 단어만 겹치고 실제 업무는 다른 경우 (예: 둘 다 "AI"를 언급하지만 하나는 신호처리, 하나는 자연어처리)를 걸러내지 못합니다. 그래서 임베딩으로 후보를 저비용으로 추린 뒤(1차), 후보에 대해서만 LLM이 실제 근거를 대며 한 번 더 정성 판정(2차)합니다 — 비용은 아끼면서 신뢰도는 높이는 2단계 구조입니다.

pipeline/show_embedding.py <사번>을 실행하면 특정 연구원 한 명을 예시로 이 임베딩 변환 과정을 실제 숫자로 확인할 수 있는 보고용 리포트가 만들어집니다.

③결과를 읽을 때 유의할 점

✓
근거 없는 매칭은 애초에 제외됩니다. "연구원 ↔ 연구원"에서 보이는 후보는 전부 LLM이 구체적 근거를 댄 경우만 남긴 것입니다 — 유사도 점수만 높고 근거가 빈 경우는 목록에서 빠집니다.
⚠
표면적 어휘 일치 ≠ 실질적 업무 일치. 두 사람이 같은 단어를 언급해도 실제 응용 분야가 다르면 낮은 등급으로 판정되고, 그 경우 "표면 일치 주의" 표시가 붙습니다.
⚠
조직도가 안 보이거나 이상해 보이면 team_refer.csv(팀참조시트.xlsx 전처리 결과)가 최신인지 확인하세요. 이 파일이 없으면 조직도 없이 부서명 평면 목록으로만 표시됩니다(오류는 아니지만 탐색이 불편해집니다).
⚠
화면은 실행 시점의 스냅샷입니다. 사람이 매번 새로 접속할 때 재계산하는 것이 아니라, 파이프라인을 실행한 시점의 결과가 파일로 저장되어 그대로 보입니다. 인사 이동·신규 과제 반영이 필요하면 아래 참조 파일을 갱신한 뒤 파이프라인을 다시 실행해야 합니다.

④참조 파일

이 기능만을 위해 별도로 준비해야 하는 원본 파일과, 각 단계가 만들어내는 결과 파일입니다. (인사기본정보·논문·특허 등 공통 기초 데이터는 대시보드 전체가 공유하는 별도 준비 과정이라 여기서는 생략합니다.)

"전문성 MAP" 탭은 별도 결과 파일이 없습니다

위 임베딩 계산 과정에서 함께 쌓이는 embedding_cache.json과 연구원 전문성 JSON을 그때그때 읽어 UMAP으로 2차원 좌표를 계산해 그리는 방식이라, 화면을 열 때마다 즉석에서 계산됩니다(별도로 저장해두는 결과 파일이 없습니다).

부록: 실행 순서 (실무자용)

아래는 데이터를 처음부터 새로 갱신할 때의 순서입니다. 조직도/과제 컨플 주소처럼 원본 엑셀만 바뀐 경우는 해당 단계만 다시 실행하면 됩니다.

python pipeline/process_team_refer.py                  # 조직도
python pipeline/process_project_confl.py               # 과제 컨플루언스 주소
python pipeline/process_project_expertise.py           # 과제 전문성 분석 (LLM)
python pipeline/process_researcher_expertise.py        # 연구원 전문성 분석 (LLM)
python pipeline/process_project_researcher_fit.py      # 과제 ↔ 연구원 매칭 (임베딩+LLM)
python pipeline/process_researcher_similarity.py --refresh-judgments  # 연구원 ↔ 연구원 유사도

위 1~2단계(전처리, LLM 비용 없음)는 python pipeline/run_expertise.py로, 3~6단계(LLM 호출, 비용 발생)는 python pipeline/run_analysis.py로 한 번에 실행할 수 있습니다. 전체를 이어서 실행하려면 python pipeline/run_integration.py를 사용하세요(실행 전 pipeline/run_ready.py로 사내 LLM/임베딩 서버 연결을 먼저 점검하는 것을 권장합니다).

이 문서는 대시보드 코드와 함께 저장소(docs/보유_전문성_가이드.html)에 보관되며, 기능이 바뀌면 함께 갱신됩니다.
