1한눈에 보기

보유 데이터로 내부 LLM이 사전 질문을 만들고, 그 질문을 실제 AI 검색과 똑같은 경로로 실행해 결과를 평가합니다. 문제가 있는 질문은 엑셀에서 올바른 접근방법을 직접 적어 규칙 · 예시 · 코드 수정 요청서로 반영하고, 같은 질문 세트를 다시 돌려 전후 점수를 비교합니다.

① 질문 만들기LLM 생성 + 데이터로 정답을 계산하는 "정답 대조" 질문
② 목록 편집수정·추가·삭제, 세트로 저장
③ 일괄 실행서버 백그라운드, 오래 걸려도 OK
④ 결과 확인정답 F1 · LLM 심사 · SQL · 엑셀
⑤ 개선 반영엑셀 수정 후 업로드 → 규칙/예시/코드
⑥ 재실행·비교이전 실행과 점수 변화 확인
안전

실제 사용자 검색에 영향 없음

테스트 실행은 일반 AI 검색 로그에 남지 않고, 시작한 관리자의 권한 범위에서만 조회합니다.

서버 실행

화면을 닫아도 계속

상태/결과를 서버 파일에 저장하므로 다른 화면으로 이동하거나 브라우저를 닫아도 이어집니다. 중지 버튼도 있습니다.

주의

자동 코드 수정은 없음

코드 수정이 필요한 건은 "코드 수정 요청서"로 내려받아 개발 쪽에서 테스트와 함께 고칩니다.

2질문 만들기

LLM 생성 질문 — 8개 카테고리

카테고리무엇을 확인하나
전문성 검색특정 기술·연구 분야 보유자 찾기
학력·나이·직급 조건학위, 전공, 나이대, 직급(CL) 같은 인사 기본 조건
유사 연구원비슷한 전문성을 가진 사람 찾기
논문·특허논문 편수, 저널, 특허 건수·등급, 대표발명자
조직·과제부서·과제·팀 소속, 조직별 인원
복합 조건조건 2~3개를 조합한 질문
동의어·오타·모호한 표현구어체·줄임말·오타·영한 혼용으로 같은 의도를 묻는 질문
지원하지 않는 질문이 데이터로 답할 수 없는 질문 — 정중히 거절하는 것이 정답

카테고리를 고르고 개수(카테고리당 1~30)를 정해 생성합니다. LLM에는 부서·직급·강점 분야·키워드·전공·학위·과제명 같은 용어 목록만 전달하고 개인 이름·평가 정보는 보내지 않습니다.

정답 대조 질문 — 데이터로 정답을 직접 계산

코드가 데이터에서 정답 사번 집합을 계산해 질문과 함께 저장합니다. AI 검색 결과와 사번 단위로 비교하므로 가장 신뢰할 수 있는 평가입니다.

  • "박사 학위를 가진 연구원" · "전공이 OO인 연구원" · "OO팀 소속 연구원 명단" · "직급이 OO인 연구원"
  • "논문을 N편 이상 쓴 연구원" · "특허가 N건 이상인 연구원" · "OO 분야 전문가를 찾아줘"
"OO 분야 전문가" 질문의 정답은 강점 분야에 그 표기가 정확히 들어간 사람입니다. 의미가 비슷한 표기까지 찾는 AI 검색은 재현율이 낮게 나올 수 있으니 점수는 참고로만 보세요.

질문 목록 관리

  • 표에서 셀을 더블클릭해 질문·카테고리를 수정, 행 추가, 체크한 행 삭제
  • 작업 목록 저장(자동 불러옴) · 세트로 저장/불러오기(이름 붙여 재사용 — 전후 비교용 고정 세트로 유용)
  • 생성 시 "기존 목록 교체"를 끄면 뒤에 추가됩니다.

3일괄 실행

옵션설명
실행 이름예: "규칙 추가 전" — 나중에 실행 이력·비교에서 구분
검색 기준현재 / 누적 (실제 AI 검색의 토글과 동일)
대상전체 또는 체크한 행만
LLM 심사켜면 정확성 점수까지 매김(질문당 LLM 호출이 늘어 느려짐)
  • 질문마다 질문 분류 → 조회(SQL 등) → 결과 설명을 실제 AI 검색과 같은 함수로 실행하고, 분류된 유형·SQL·결과 일부·설명·소요 시간을 기록합니다.
  • 한 번에 한 작업만 실행됩니다(이미 실행 중이면 안내). 진행 줄에 경과 시간·완료 개수·현재 질문이 표시됩니다.
  • 서버 재시작 등으로 5분 넘게 갱신이 없으면 중단된 것으로 표시합니다. 중지 시 지금까지의 결과는 저장됩니다.

4품질 평가 — 세 겹

1

기계적 검사

  • error 오류
  • unsupported 미지원 답변
  • empty 0건
  • slow 60초 초과
  • truncated 결과 잘림
  • no_answer_text 설명 없음
2

정답 대조

기대 사번과 반환 사번을 비교해 정밀도 · 재현율 · F1을 계산하고, 빠진 사번/기대에 없던 사번 예시를 보여줍니다.

3

LLM 심사

질문 · 분류 유형 · SQL · 결과 상위 10행 · 설명을 보고 1~5점 + 문제 유형 + 이유를 냅니다. 참고용 점수입니다.

상태 판정

상태조건(요약)
양호오류·0건·잘림 없음, 정답 F1 0.8 이상, 심사 4점 이상
주의0건 / 60초 초과 / 결과 잘림 / F1 0.5~0.8 / 심사 3점
실패오류 / 미지원 답변 / F1 0.5 미만 / 심사 2점 이하
지원하지 않는 질문거절하거나 0건이면 양호, 결과를 내놓으면 실패(심사 4점 이상이면 주의)

문제 유형(심사): 조건 누락 · 조건 오해석 · 컬럼/표 선택 오류 · 결과 과다 · 결과 없음 · 거절해야 하는데 답함 · 거절이 부적절 · 기타

5결과 · 비교 · 엑셀

  • 결과 표: 상태 · 카테고리 · 질문 · 유형 · 건수 · 시간 · 정답 F1 · 심사 · 문제 유형 · 플래그 (정렬/필터). 요약 배지에 양호/주의/실패 개수와 평균 점수.
  • 상세: 행을 클릭하면 생성된 SQL, 결과 일부, 시스템 설명, 심사 이유, 정답 대조(빠진/초과 사번 예시)가 나옵니다.
  • 이전 실행과 비교: 비교할 실행을 고르면 질문별 이전 상태·이전 심사·심사 변화 열이 표시됩니다.
  • 엑셀: 결과 / 요약(카테고리별) / 작성 방법 / 개선 제안 시트.
  • 개선 제안: 양호가 아닌 질문들을 묶어 LLM이 "규칙 설정"에 넣을 규칙 문장 3~8개를 제안합니다(자동 적용 안 됨 — 검토 후 반영).

6개선 반영 — 엑셀을 직접 수정해서 올리기

결과 엑셀의 "결과" 시트 오른쪽 끝 노란 열 5개를 잘못된 질문의 행에만 채웁니다.

열내용
올바른 결과/접근방법이 질문은 어떻게 풀어야 하는지 자유롭게 서술
올바른 SQL(선택) 정답을 만드는 읽기 전용 SELECT — 올리면 실제로 실행해 검증
기대 사번(선택) 정답 사번 목록(쉼표/줄바꿈 구분) — 정답 대조 질문으로 자동 편입
반영 구분규칙 / 예시 / 코드 / 무시 (드롭다운, 비우면 건너뜀)
규칙 문장반영 구분이 "규칙"일 때 쓸 한 줄(300자 이내)

업로드 후 — 미리보기와 검증

수정한 엑셀을 ⑤ 영역에 올리면 항목마다 반영될 내용과 검증 결과가 표로 나옵니다. 올바른 SQL은 허용 여부를 확인한 뒤 읽기 전용으로 실행해 건수와(기대 사번이 있으면) 정답 대조 F1을 보여줍니다. 체크한 항목만 "선택 항목 반영"으로 적용하며, 검증에 실패한 항목은 반영되지 않습니다.

규칙

모든 질문에 즉시 적용

  • "규칙 설정"의 자동 관리 블록에 한 줄씩 추가 — 수기 규칙은 건드리지 않음
  • 같은 문장은 중복 건너뜀
  • 전체가 4000자를 넘으면 아무것도 바꾸지 않고 거부
예시

비슷한 질문에 예시로 첨부

  • 질문 → 올바른 접근/SQL을 "검증된 예시"로 저장
  • 비슷한 질문(임베딩 유사도 0.75 이상, 정확히 같으면 임베딩 없이도)이 오면 최대 3건을 질문 분류·SQL 생성 프롬프트에 첨부
  • 같은 질문 재반영 시 갱신
코드

코드 수정 요청서

  • 서버는 코드를 바꾸지 않음
  • 질문 · 시스템 판정 · 심사 이유 · 시스템 SQL · 올바른 접근/SQL · 기대 사번이 담긴 마크다운 문서를 내려받음
  • 개발 쪽에서 스크립트 수정 + 테스트 + 커밋

무시는 기록만 남깁니다. 기대 사번을 적은 항목은 반영 구분과 무관하게 테스트 질문 목록의 정답 대조 질문으로 편입/갱신됩니다.

규칙 vs 예시, 어떻게 고를까? 여러 질문에 공통으로 적용되는 용어 정의·해석 기준이면 규칙("상위평가는 가/나 등급이다"). 특정 유형의 질문을 이렇게 풀라는 구체 사례면 예시. 프롬프트로 해결이 안 되는 로직 문제면 코드.

7관리 · 이력 (⑥ 영역)

  • 반영된 규칙/예시를 표로 보고 켜기 · 끄기 · 삭제 — 끄면 즉시 AI 검색에서 빠지고(기록 유지), 삭제하면 목록에서도 사라집니다.
  • 모든 반영·변경은 이력 파일에 남습니다(누가 · 언제 · 어떤 질문 때문에).
  • 규칙을 켜거나 추가할 때 4000자를 넘으면 처리하지 않고 사유를 알려줍니다.

8운영 가이드

권장 사용 순서

  1. 처음에는 카테고리당 3~5개만 생성하고 5~10개 질문으로 실행해 흐름과 소요 시간을 확인합니다.
  2. 질문 세트를 다듬어 이름 붙인 세트로 저장(전후 비교의 기준이 됨).
  3. "반영 전" 이름으로 실행 → 실패/주의 질문을 엑셀에서 수정 → 업로드·반영.
  4. 같은 세트를 "반영 후"로 다시 실행하고 이전 실행과 비교해 점수가 올랐는지 확인.
  5. 점수가 오르지 않거나 다른 질문이 나빠졌으면 ⑥에서 해당 규칙/예시를 끄고 다시 비교.

알아두세요
  • 규칙과 예시는 모든 사용자의 검색에 영향을 줍니다. 한 번에 여러 개를 넣기보다 소수씩 반영하고 전후를 비교하세요.
  • LLM 심사 점수는 참고용입니다. 정답 대조(F1)가 있는 질문을 최우선 지표로 보세요.
  • 하위 화면에서 보이는 권한 범위(평가 등 권한이 필요한 데이터)는 실행한 관리자 계정 기준입니다. 권한/대상자별 필터링은 추후 확장 항목입니다.
  • LLM 동시 호출 슬롯은 실제 검색과 공유됩니다. 업무 시간 중 대량 실행은 피하는 것이 좋습니다.
